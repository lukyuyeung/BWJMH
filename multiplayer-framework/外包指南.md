# 外包指南（契約 0.18）

這份說明一款 Bunny Gala 遊戲要寫哪些東西。型別的唯一來源是 `contract/src/index.ts`；這裡逐條解釋，並附範例的程式碼位置。

## 1. 平台怎麼跑一款遊戲

```
瀏覽器（你的畫面 GameView）  ⇄  平台的牌桌引擎（伺服器）  ⇄  你的規則 GameLogic
        只送動作、只畫畫面            發牌、計時、機器人、扣款、派彩          純函式，算輸贏
```

- **規則在伺服器跑**。發牌、機器人、計時、預扣、派彩都由平台負責。
- 瀏覽器只會收到 `privateView(state, seat)`，也就是這個座位看得到的東西，然後送出玩家的動作。
- 遊戲程式**不開 socket、不碰紅蘿蔔**。紅蘿蔔一律透過 `liability()` 和 `result()` 告訴平台。

一款遊戲分兩部分：
- `src/game.ts` 匯出 `logic`（`GameLogic`）：伺服器只 import 這個檔，所以不能碰 DOM。
- `src/index.ts` 匯出 `game`（`GameModule` = `logic` + `view`）：牌桌頁用 `playGame(game, el)` 掛上去。

## 2. 硬規則（違反了 `npm run check` 會抓到，或上線後出事）

1. **規則裡不能用 `Math.random`，也不能碰 DOM。** 亂數只能來自 `ctx.draw`。
2. **不能改傳進來的 state。** `reduce` 每次都要回傳新的物件。
3. **state 只能放 JSON 能存的東西**：數字、字串、布林、陣列、一般物件。不能放 Map、Set、Date、class、函式。
4. **暗牌一定要經過 `privateView`。** `random: "server"` 的遊戲沒有 `privateView`，平台會拒絕載入。每款遊戲都要在 `tests/` 寫一個 privateView 測試，範例見 `games/carrot-duel/tests/privacy.test.ts`。
5. **`liability()` 必須是 0 或正整數**（帳本只收整數紅蘿蔔），不能超過 `ctx.limits.maxStake`，開局的金額不能比 `minStake` 多。**`dealt()` 為 true 之後只能維持或增加，不能減少。**
   平台只在 `create()` 之後和**玩家或機器人動作之後**鎖紅蘿蔔，**draw 之後不會鎖**：不要讓 liability 在 draw 時變多，那部分不會被扣，派彩卻會付出去。
6. **派彩要包含退回的本金。** 押 10、贏 1 賠 1，派彩是 20。
7. **gameId 要等於資料夾名稱**，`web/vite.config.ts` 的 `base` 要是 `/play/<gameId>/`。
8. **玩家名字是玩家自己取的任意文字。** 放進 `innerHTML` 之前一定要跳脫，或改用 `textContent`。不然有人把名字取成 `<svg onload=…>`，就能在同桌每個人的瀏覽器裡執行程式。範例見 `games/carrot-duel/src/view.ts` 的 `escapeHtml`。

## 3. `ctx`（RoundContext）

伺服器每一手都會給你一個 `ctx`：

| 欄位 | 說明 |
|---|---|
| `mode` | `casual`（押紅蘿蔔）或 `ranked`（排位，用籌碼，目前沒開） |
| `room` | `beginner` / `intermediate` / `advanced` / `god` |
| `seats` | 每個座位：`seat`、`bot`（是不是機器人）、`displayName`、`stakeCap`（這手最多能鎖多少） |
| `you` | 這個 ctx 是給哪個座位的。**在伺服器上是 -1**（規則不能依賴誰在看）；單人遊戲例外，是玩家的座位 |
| `pveBanker` | 有莊家時是莊家的座位（**永遠是 0**），沒有時是 null |
| `options` | 大廳的選擇（`tableOptions`）加上上一手留下的（`nextOptions`），還有 `tableId` |
| `draw` | 平台揭曉的亂數，只在伺服器上有，瀏覽器永遠拿不到 |
| `handNo` | 這一桌第幾手（從 0 開始），可以用來輪流當先手 |
| `limits` | 房間的限額：`unit`、`minBet`、`maxBet`、`maxStake`，見 `docs/LIMITS.md` |

**座位編號**：有莊家（`pve: true`）時，座位 0 是莊家，玩家從 1 開始；沒有莊家時從 0 開始。

**`ctx.draw` 怎麼用**：它是 16 個 0–51 的數字，**可能重複，不是一副牌**。要像範例的 `shuffleFromDraw`（`games/carrot-duel/src/logic.ts`）那樣，拿它當種子洗出一副牌。同一組 draw 永遠洗出同一副牌，所以伺服器重算也會得到一樣的結果。需要更多亂數時，讓 `needsDraw()` 再回傳 true，平台會給下一組。

## 4. GameLogic（規則）逐條

範例：`games/carrot-duel/src/game.ts`（每一行都有註解）、`games/fortune-3-card/src/game.ts`。

### 基本資料

- `gameId`：遊戲 id，必須等於資料夾名稱。
- `pve`：有沒有莊家。`true` 時平台會在座位 0 放一個莊家機器人，莊家不扣錢，輸贏由平台帳本出。玩家對玩家的遊戲填 `false`。
- `seats`：玩家座位數（不含莊家）。`1` 是一人對莊家；`2` 以上是多人同桌，沒有真人的座位由機器人坐。
- `random`：`"server"` 表示有暗牌或亂數，平台先公布雜湊（`ctx.commit`），押注鎖定後才揭曉 `ctx.draw`。`"none"` 表示沒有隱藏的亂數。
- `turnMs`：每一輪行動的時間（毫秒），伺服器強制執行。超時的人由 `fallback` 代打。
- `extendMs`：玩家每輪可以要求一次的加時（`HostApi.extend`）。不填或 0 表示不能加時。
- `rules`：規則面板的 `{ title, body }`，大廳的規則按鈕會用到。

### 一手牌的流程

- `create(ctx)`：開一手，回傳初始 state。
- `reduce(state, action, ctx)`：套用一個動作，回傳新的 state。動作不合法時（不是你的回合、金額不對）**回傳原本的 state**。
- `needsDraw(state)`：規則需要亂數時回傳 true。平台會把 `ctx.draw` 填好，再呼叫 `reduce(state, { type: "draw" }, ctx)`。
- `actors(state)`：現在可以行動的座位。空陣列表示在等（例如等發牌）。一個座位就是輪流；兩個以上就是同時下注，等大家都動了或時間到。
- `dealt(state)`：牌、骰子或結果已經露出來時回傳 true。之後平台就不會作廢退錢。
- `result(state)`：這一手結束時回傳 `{ payouts, result }`，沒結束時回傳 null。
  - `payouts`：`[{ seat, payout }]`，**包含退回的本金**。莊家不用列。
  - `result`：給畫面用的結果資料，例如誰贏、開了什麼牌。
- `matchOver(state, ctx)`：只有排位賽用得到。沒有排位賽就回傳 `false`。

### 紅蘿蔔

- `liability(state, seat, ctx)`：這個座位現在要鎖在桌上多少紅蘿蔔（所有注加起來）。平台只會再鎖增加的部分；押不起時會拒絕這個動作，玩家可以重下。`dealt()` 之後只能維持或增加。莊家座位和排位賽回傳 0。
- `maxPayoutMultiple`：一手最多能贏到押注的幾倍（含本金）。超過的派彩平台會當成 bug 並封頂。預設 41。
- `minStake(limits)`：坐下至少要付得起多少（例如底注加一次跟注）。平台只讓付得起的人進房間。預設是一個 `minBet`。

### 機器人和代打

- `bot(state, seat, ctx)`：機器人的動作。莊家和所有機器人座位都靠它；多人遊戲一定要寫。
  - 建議讓 `bot()` 對玩家座位也能下最小注，這樣 `npm run check` 的規則模擬才打得到結算、驗得到派彩。
- `fallback(state, seat, ctx)`：玩家超時或離開時伺服器幫他走的動作，通常是「不加注」「棄牌」「停牌」。同時下注的遊戲用「不再下注」。

### 暗牌

- `privateView(state, seat, ctx)`：這個座位看得到的畫面。伺服器只把它送給那個座位。
  - 只給自己的牌；別人的牌要等亮出來才給。
  - `seat` 是 -1 時是觀戰者（中途進來的人），誰的暗牌都不能給。
  - 不能把整副牌、`draw` 或還沒發的牌放進去。

### 多人桌（online）

- `tableOptions`：大廳的選擇，例如 `{ deck: ["full", "short"] }`。牌桌頁從網址（`?deck=short`）讀，伺服器只把選一樣的人湊到同一桌，規則從 `ctx.options.deck` 讀。玩家在桌上不能改。
- `nextOptions(state, options)`：一手結算後要帶到下一手的資料，會合併進下一手的 `ctx.options`。例如累積的等級、這一桌打了幾手。
- `restMs`：多人桌一手結束後顯示結果多久才開下一手。預設 5000。多人桌一定會等滿這段時間。（一人對莊家的桌子不看 `restMs`：它會等玩家呼叫 `HostApi.startCasual` 才開下一手。）
- `liveTurns`：動作一送到就生效，同一輪可以送很多次（例如連續放好幾個籌碼，最後按「完成」）。等 `actors()` 裡沒有還在等的人，或時間到（剩下的人用 `fallback`），這一輪才結束。不設定時，每個座位每輪只送一個動作，大家都送了才一起套用。
  - 適合：下注桌、骰子桌這種大家同時放籌碼的遊戲（平台的 Craps 用它）。
  - 不適合：輪流行動的牌桌。

**動作裡的 `seat`**：動作可以帶 `seat`（例如 `{ type: "call", seat: 2 }`）。伺服器一定會把它改成**送出這個動作的人**的座位，所以沒有人能冒充別人；規則只要檢查它是不是現在的 actor。

**中途加入**：多人桌打到一半才進來的人會先觀戰（`ctx.you` 是 -1，看到的是 `privateView(state, -1)`），可以呼叫 `HostApi.takeSeat(seat)` 接手某個機器人的座位，下一手開始發牌給他。

**斷線**：斷線的座位由 `fallback` 代打，30 秒內回來可以接著打。

**多人桌不能用 `setOptions`**：同桌的人選擇要一致，所以只能用 `tableOptions`。

## 5. GameView（畫面）逐條

範例：`games/carrot-duel/src/view.ts`。

- `mount(el, host)`：把畫面掛到 `el`。`host` 是你和平台溝通的唯一管道，先存起來。桌子畫好後呼叫 `host.ready()`。
- `render(view, ctx)`：每次伺服器送來新畫面就會呼叫。`view` 是 `privateView` 的結果，`ctx.you` 是自己的座位（-1 是觀戰）。**只畫這些資料，不要自己算輸贏。**
- `deadline(at)`：伺服器的倒數截止時間（UTC 字串），沒有人在計時時是 null。用它畫倒數。
- `dealHold()`：發牌動畫還要幾毫秒（選填）。伺服器的計時已經預留了幾秒動畫時間。
- `motionHold()`：其他動畫還要幾毫秒（選填）。
- `destroy()`：離開時清掉計時器和畫面。

## 6. HostApi（畫面能呼叫的）

- `session()`：玩家資料、紅蘿蔔、各房間的限額和能不能進（`rooms`）。
- `ready()`：畫面準備好了，呼叫一次。
- `startCasual(room)`：坐進這個房間。已經坐著時，意思是「開下一手」：一人對莊家的桌子靠它開下一手（畫面要有「再來一手」之類的按鈕）；多人桌照 `restMs` 計時，呼叫了也不會提早。
- `startRanked(ladder)`：排位賽，目前還沒開放，會回錯誤。
- `act(action)`：送出玩家的動作。
- `extend()`：要求這一輪加時（需要 `extendMs`），每輪一次。
- `setOptions(options)`：單人桌改選項。多人桌會被忽略，請用 `tableOptions`。
- `takeSeat(seat)`：觀戰時接手一個機器人的座位，下一手開始加入。
- `fact(name, payload)`：成就事件，例如 `fact("royal-flush")`。獎勵由平台決定（目前還沒接）。

## 7. 頁面（web/）

- `web/index.html` 是你的大廳：選房間、選 `tableOptions`，然後打開 `play.html?room=…&<選項>=…`。
  - 練習時網址的 `?name=` 代表玩家，要一起帶過去（看 `games/carrot-duel/web/lobby.ts`）。
- `web/play.html` 是牌桌：`playGame(game, el)` 會登入、掛上畫面、依 `?room=` 坐下。
  - 畫面如果有自己的房間選擇，用 `playGame(game, el, undefined, { autoStart: false })`，自己呼叫 `host.startCasual(room)`。
- 房間資料（`minBet`、`entry`、`allowed`）從 `/v1/casino/games` 讀（`callApi(playConnection, "/v1/casino/games")`）。
- 返回鍵、橫屏、音樂和音效**用平台共用的**，見 `docs/共用元件.md`。
- 美術放在 `web/public/`，用相對路徑引用（`assets/…`），因為正式環境掛在 `/play/<gameId>/` 底下。

## 8. 限額

每個房間只有一個數字 `unit`（新手 10、中級 100、高級 1,000、神級 10,000），其他都是它的倍數：`minBet` = 1 unit、`maxBet` = 100 unit、`maxStake`（一手所有注加起來）= 300 unit。
遊戲的注額請用 `ctx.limits` 表示，不要自己寫死數字，這樣平台調整房間時每款遊戲會一起變。數字目前是暫定的，見 `docs/LIMITS.md`。

## 9. 測試

- `npm test` 會對 `games/` 裡每一款遊戲自動跑：
  - 規則模擬
  - 在真的牌桌引擎上讓伺服器代打，檢查帳本和有沒有洩漏 draw
  - 多人遊戲的入座、接手座位、斷線
- 你自己要寫的：`tests/privacy.test.ts`（必須）和規則的單元測試（建議），範例見 `games/carrot-duel/tests/`。
