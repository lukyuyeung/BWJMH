# 交件清單

## 一、自動檢查（必須全部 ✔）

```bash
npm run check <遊戲id>
```

它會檢查：

1. 資料夾結構：`package.json` 的 name 和 exports、`src/game.ts`、`web/vite.config.ts` 的 base
2. 伺服器能載入：gameId 等於資料夾名稱；有暗牌就一定要有 privateView
3. 型別檢查
4. 規則模擬：機器人打 200 手（每種 `tableOptions` 組合都打），檢查以下幾件事：
   - 有沒有用 `Math.random`
   - 有沒有改傳入的 state（任何函式都不能改，包括 bot、liability、privateView）
   - liability 是不是 0 或正整數、有沒有超過 maxStake、開局有沒有比 minStake 多、有沒有在 draw 時變多
   - privateView 會不會出錯
   - 多人桌的機器人能不能把每一手打下去
   - state 能不能存成 JSON
   - 每一手會不會結束
   - `dealt()` 之後 liability 有沒有減少
   - 派彩有沒有超過 `maxPayoutMultiple`
   - 玩家對玩家的遊戲，派彩總和是否等於押注總和
5. `tests/` 裡有 privateView 測試
6. 頁面能建置（vite build）
7. 全部測試通過

出現 ⚠ 時請在交件說明裡寫原因。例如「機器人不會開局」：一人對莊家、要玩家先下注的遊戲可能會出現；建議讓 `bot()` 對玩家座位也能下最小注。

## 二、人工檢查

- [ ] 在 812×375 橫屏下，大廳和牌桌都沒有重疊、沒有被切掉
- [ ] 返回鍵在左上角，和右上角的按鈕對齊、大小一致
- [ ] 大廳的返回鍵回到首頁；牌桌的返回鍵回到大廳
- [ ] 切到別的分頁或 App 背景時，聲音會停；音樂和音效開關都有效
- [ ] 規則面板（`rules`）的文字寫好，和實際規則一致
- [ ] 多人遊戲：用 alice、bob 兩個分頁同桌打過，中途加入的人能接手座位，有人關掉分頁時牌局繼續
- [ ] 沒有抽菸、喝酒的畫面
- [ ] 美術符合 `docs/美術風格/`：圖標、按鈕三態、像素兔子
- [ ] 美術和音效都放在 `web/public/`，沒有連到外部網址

## 三、怎麼交

1. 把整個 `games/<遊戲id>/` 打包成 zip（不要包 `node_modules`）。
2. 附上 `npm run check <遊戲id>` 的完整輸出。
3. 附一段說明：玩法、`tableOptions` 的意思，以及任何 ⚠ 的原因。

不要交 `contract/`、`platform/` 的修改。如果你覺得平台少了什麼，請另外寫給我們。
