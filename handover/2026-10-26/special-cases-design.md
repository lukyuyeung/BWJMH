# 日麻特殊情況：規則、演出與真人框架接入定案

日期：2026-10-26（香港）  
狀態：遊戲設計完成；下列新增規則尚未接入公開版。不能把本文件視為已上線或測試通過的功能。  
依據：玩家已採用包牌及流局滿貫，並同意雙響特殊演出、多倍役滿、重連同步、播放失敗及持久結算的處理方向。現有已實作項目另見 `app-source/docs/multiplayer-flow58.md`。

## 1. 不改動的對局基準

四人東風戰，起始每人 25,000 點。新手場／中級場／高級場入場紅蘿蔔為 2,500／25,000／250,000，出牌 30／20／10 秒；搶牌獨立 12 秒，不因有人先按吃碰重設。出牌超時持續代打，回應超時視為放過；斷線保留帳號座位與輸贏，主動返回才恢復操作。新裝置取得控制權，舊裝置立即失去操作權。

同一結算的所有收支、供託及本場先一次計算，再檢查任何人 ≤0 的破產終局。雙響、多人流局滿貫不能付款到一半提前結束。終局供託給第一名，同分按初始座次；總點數連同未領供託必須守恆至 100,000。

吃斷、赤牌開啟；不採切上滿貫。累計役滿固定一倍，不因 26 番變雙倍；真正役滿可疊加。暫不引入單一役種特殊雙倍（國士十三面、純正九蓮、四暗刻單騎、大四喜加倍）；大四喜仍為一倍，與其他役滿合計才增加倍數。此為本遊戲固定變體，規則頁必須明寫。

## 2. 同張牌的搶牌裁決

1. 伺服器建立唯一 `claimId`、共同截止時間和每席合法選項；`actors()` 同時列出仍待回應者，不能只列第一位。
2. 榮和 > 碰／大明槓 > 吃；碰／大明槓同級按放銃者下家起順序。吃僅下家合法。
3. 先按吃／碰只記錄意向，顯示「等待其他玩家回應」。不能先露出副露或推進摸牌，也不公開哪一家仍能和。
4. 全部有榮和機會者回覆或到期，才能判一響、雙響或三家榮和流局。**三家都有機會但只有兩家選榮和，仍為雙響。**
5. 雙響按放銃者下家起排序演出；兩家各自收和牌點及本場，供託一次給較近的一家。有任一贏家為莊家則連莊。
6. 三家實際宣告榮和：不付和牌分、不領供託，本場 +1、莊家不移。蓋過已暫存的吃碰；不播放任何贏家影片。
7. 放過合法榮和依現有振聽規則處理；立直後放過榮和為本局立直振聽。不能以稍後按碰或重連消除。
8. 相同動作 ID 重送回覆原結果；同一搶牌只接受每席首次有效決定，過期／不同手局／非本人操作一律拒絕。伺服器收到時間裁定截止，截止後才到的封包不補算。

## 3. 包牌／責任支付（新增採用）

### 觸發與保存

只採 **大三元、大四喜** 兩種責任；不採四槓子包牌或其他地方變體。

- 已有兩組明刻／明槓三元牌，再由某人打出最後一種三元牌，讓同一玩家碰／大明槓成第三組：記錄該出牌者對大三元負責。
- 已有三組明刻／明槓風牌，同樣由最後一次碰／大明槓湊齊第四種：記錄大四喜責任。
- 暗刻／暗槓不視為事前已公開的責任組數；自摸完成的最後組不產生責任。原碰牌加槓不另產生責任、不更換原責任人。
- 責任在副露正式裁決成功後記錄；若同張牌被榮和、搶槓或三家榮和截斷，不能先寫入責任。
- 每筆保存 `beneficiarySeat / liableSeat / yakuId / triggeringEventId`；與手局狀態一同保存。真正和牌沒有該役滿，該筆不收款。每新局清除。

### 付款規則

把和牌拆成「負責的役滿單位」與「其餘役滿單位」，分開算後相加，**不得將全手牌所有役滿轉嫁給包牌者**。

| 和牌方式 | 負責的役滿單位 | 其他單位 |
| --- | --- | --- |
| 自摸 | 責任者支付該單位的全部自摸總額 | 按正常莊閒自摸分配 |
| 別人放銃 | 責任者、放銃者各支付該單位榮和額的一半 | 由放銃者支付 |
| 責任者自己放銃 | 責任者支付全部 | 責任者正常支付 |

本場只算一次：自摸且有包牌時，由責任者另付每本場 300；榮和由實際放銃者另付每本場 300。不按役滿倍數放大本場。供託不拆分，雙響仍依第 2 節分配。若未來引入同手多種責任，本場不能重複向多名責任者收取；目前大三元與大四喜無法同手成立。

例：閒家大三元＋字一色，雙倍役滿；A 包大三元，B 放銃。A 付 16,000，B 付 48,000，贏家共收 64,000（另計本場）。同手自摸：A 付負責單位 32,000，再付字一色正常自摸份額；其他兩家只付字一色份額。

### 畫面

碰成責任組時，相關副露旁短暫出現小型「責任」印記，無全桌打擊或警報。和牌影片／役滿演出保持原順序；役種計算後，在付款明細寫「大三元責任支付」，列實際付款人和金額。點數轉移按真實付款邊畫線；責任者與放銃者相同時合併一條，不畫兩次。

## 4. 流局滿貫（新增採用）

### 成立條件與競合

僅正常牌山耗盡的荒牌流局檢查；九種九牌、四風連打、四家立直、四槓散了、三家榮和不檢查。

每家獨立判定：至少打過一張牌；自己全部捨牌都是么九牌；其中沒有任何一張被吃、碰、大明槓；自己全局沒有吃碰槓（本作連暗槓亦使資格失效）。不要求聽牌；立直不使資格失效。被榮和的最後一張先完成榮和，不再判流局滿貫。

- 副露時只使**副露者**及**被叫走捨牌者**失去資格，不波及其他人。
- 自己曾打中張牌，之後那張被吃碰掉仍不恢復資格。必須保留完整河牌及被叫走標記，不能只掃目前可見河牌。
- 多家同時成立全部有效；互相亦按自摸付款，先各算再合併淨額。不是雙響，也不觸發三家榮和流局。
- 不再進行不聽罰符。每位成立者按滿貫自摸收款：莊家每家 4,000；閒家向莊家收 4,000、其他人各 2,000。每本場向其餘每家另收 100，合併淨額後一次入帳。
- 供託只發一次，給從當局莊家起東南西北順序首位成立者。若莊家成立則連莊且本場 +1；否則輪莊且本場歸零。本作將流局滿貫作為和了處理，不以未成立莊家的聽牌保留莊位。
- 例：東、南同時成立，無本場供託：東淨 +8,000；南淨 +4,000；西、北各 -6,000；總和 0。

### 畫面

牌山耗盡 → 暗場 → 「流局滿貫」金色標題 → 成立者的**捨牌河**依次受鎂光燈照亮 → 顯示收支 → 共用點數轉移。多人成立用並列河牌和角色小像，總展示約 4 秒，不連播多支滿貫動畫。

**不揭開未和牌手牌、不顯示假的和牌張、不播清一色影片。** 役種頁使用流局滿貫專用條目與付款明細，不拿手牌跑一般番符計算；結果資料必須有獨立種類 `nagashi_mangan`。

## 5. 特殊和牌的演出排程

伺服器先完成整手判定，生成固定 `presentationPlan`（手局 ID、計畫 ID、每段起迄、贏家、資產及結果版本），所有裝置跟同一計畫。影片／圖片失敗不改點數，也不能延遲其他人的排程。

| 情況 | 排程 |
| --- | --- |
| 單人滿貫以上，無專用片 | 立即全桌暗場 → 該角色眼部 CUT-IN → 真實和牌及副露 → 完整角色主圖衝擊 → 役種 |
| 有清一色／役滿等專用片 | 立即暗場 → 專用片 → 役種；不疊加滿貫圖、不重複翻牌 |
| 雙響 | 0.8 秒「雙響」及兩人小像 → 依放銃者下家順序，各播一次自己的專用片或級別演出 → 兩份役種 → 共用付款 |
| 一人有片、一人無片 | 各按自己分類播放，不能用第一人影片蓋掉另一人的演出 |
| 同一人多個可播役種 | 只播一支，不串接所有影片：按下列固定優先表選擇 |
| 三家榮和 | 冷白／墨色「三家榮和・流局」約 1.8 秒 → 本場及供託說明；不做贏家演出 |
| 流局滿貫 | 使用第 4 節專用河牌演出 |

專用片優先：役滿片優先於普通役種片；多個役滿可播片時，本作固定 **大四喜 > 大三元 > 四暗刻 > 其他役滿（按資產登錄固定順位）**。沒有對應片的役滿不借用錯誤役種影片。役滿牌不得改播較低級清一色片；找不到任何適用役滿片時改播實際倍數的役滿主圖。優先表不影響計分。

三倍或以上役滿：計分按實際役滿數；視覺沿用最高級主圖，去掉原本烙印「雙倍」字樣，另以清晰動態字顯示「三倍役滿／四倍役滿／N倍役滿」。同一主圖只打擊一次，總時長封頂 6.9 秒，不按倍數重播。專用影片存在則照前述優先播放，片後以短疊字標明實際總倍數；役種頁列出所有役滿及各自倍數。

滿貫級別展示使用已完成四角色 × 六級素材；全桌保留暗場，主要光線、手牌和角色效果局限該名贏家的展示區。役種計算時不再播滿貫打擊。雙響兩人的手牌資料必須從各自結果取得，不能重用第一人。若同一張實體榮和牌在兩份報告各出現，僅作兩人的結算展示，不將其重複加入真實牌山。

## 6. 流局、槓與立直邊界

| 事件 | 固定處理與演出 |
| --- | --- |
| 九種九牌 | 第一巡、無副露打斷且符合條件，由本人選擇；超時正常代打不自動宣告。簡短流局原因，連莊、本場 +1、供託保留 |
| 四風連打 | 無副露打斷，四家首張同一風；先解決最後張可能榮和，再判流局；同上 |
| 四家立直 | 第四家宣言牌先等榮和；若被和，未成立的立直棒不收。四家真正成立才流局，本場 +1、供託保留 |
| 四槓散了 | 四槓由兩家以上完成，先保留第四槓嶺上和牌與其後捨牌榮和機會，再流局；一人四槓繼續，禁止第五槓。搶槓未完成不增加槓數 |
| 加槓被搶 | 不補嶺上牌、不增新槓寶牌、不留下完成加槓的動畫；先收集所有榮和，仍適用雙響／三家榮和 |
| 暗槓被國士搶 | 本作固定不採，規則頁標示；不向玩家提供不合法按鈕 |
| 立直後暗槓 | 僅引擎確認不改聽牌及合法牌型結構時提供；不能只比對張數或讓前端判定 |
| 海底／河底 | 依實際最後一張正常摸牌／其捨牌判定；嶺上與搶槓不誤算海底河底；無補牌資源不能槓 |
| 荒牌無流局滿貫 | 聽牌／不聽公開按規則展示，正常 3,000 點不聽罰符；莊家聽牌連莊、否則輪莊，本場 +1、供託保留 |
| 東四結束 | 莊家符合原有連莊可續；莊家和了為首位時採和了止；東四輪莊即終局，沒有西入或南入。流局滿貫視作和了，適用同一和了止判斷 |
| 中途有人 ≤0 | 完成整批當局結算後進終局，不再發牌；動畫仍完整顯示已成立結果 |

立直刮牌：能否自摸的按鈕須等玩家**實際揭開足夠辨識該摸牌**才顯示，鍵盤、輔助標籤、聲音及私有 view 的提示也不得提前洩漏可和。伺服器保留合法性判定，刮牌只控制呈現；未刮開超時由既定代打處理，不無限延長回合。這不允許前端自報牌值或改變伺服器摸牌。

## 7. 重連、背景與資產失敗

- 新裝置／重連先驗證平台帳號及座位擁有權，撤銷舊連線；拉取目前私有快照、手局 ID、事件版本、結果階段及伺服器截止時間。不能信任前端 playerId。
- 牌局中：先保持代打，按「返回自己操作」才退出；操作交接在伺服器事件邊界完成，不取消已接受的 Bot 行動。
- 演出中：進入當前段落及時間位置；若無法 seek，跳到該段靜態主圖並等剩餘時間，不重播整段。
- 役種中：顯示目前結果，可直接列齊已完成條目；不要求所有其他人重新數一次。點數轉移中按共同 deadline 顯示進度；已下一局則直接回牌桌。
- 人聲結束後，各有效真人回報一次全部役種計算完成；全員完成後停 3 秒 → 點數轉移 3 秒 → 下一局／終局。離線及持續代打者不阻塞；既有 60 秒安全上限保留。斷線後重連不得重設全桌上限。
- 圖片載入最長 8 秒，失敗顯示同角色原圖＋正確級別；影片 5 秒仍未可播放或中途停滯 3 秒，切靜態卡。這些是本機等待上限：若共同段落已結束，立即追上主機，不另加等待。
- 自動播放被擋則靜音播放，聲音失敗略過旁白；沒有聲音裝置亦可完成役種回報。顯示頁重載不能重放付款、震動或重複送完成事件。
- 減少動態模式：保留暗場、靜態眼部／主圖、真實牌及文字；取消閃白、震屏與高速切入，段落總時間不拖長。
- 同局不同裝置資產失敗互不影響；付款從結果讀取，絕不能從播放完成 callback 執行。

## 8. 與已提供 framework 的確切對接

已核對 `multiplayer-framework/src/index.ts`、`platform/src/tables/table.ts`、`LIMITS.md`。這是可重用的平台契約與練習伺服器；不是缺少 framework。以下是接駁時必須解決的實際差異，不能聲稱目前已支援。

| framework 現有介面／行為 | 麻雀接入設計 |
| --- | --- |
| `GameLogic`／`GameModule`, `seats`, `random` | `seats:4`, `pve:false`, `random:'server'`；伺服器種子派生各局牌山，不使用 Math.random；前端只使用 view |
| `create/reduce` | 一個平台財務 hand 包含**整場東風戰**，麻雀每一局是內部 subHand。否則每局結算會誤重新鎖入場及換座 |
| `result` | 東風戰結束才回傳平台 HandResult；每局和牌使用內部 settlement，不觸發平台派彩 |
| `actors`, `liveTurns` | `liveTurns:true`；列出所有未決搶牌席，意向交由麻雀 reducer 排序；reduce 不可原地污染舊 state |
| `privateView` | 各席／旁觀者完全分開，隱藏別人手牌、牌山、種子、合法搶牌提示與復原憑證；旁觀 `seat:-1` 不看任何暗牌 |
| `bot/fallback` | Bot 必須產生合法可推進行動；出牌 fallback 開啟持續代打，搶牌 fallback 只放過；不能把原帳號改為財務 Bot |
| 單一常數 `turnMs`，另加 `graceMs` | 現契約不能表達出牌 30/20/10 和搶牌 12；需平台提供階段 deadline／動態 turn time，並消除額外 grace 對實際規則時限的改動，不能只改前端倒數 |
| `actors:[]` 主迴圈直接退出 | 不可用空 actors 等 3 秒動畫，否則被當作無結果中止；需平台內部排程／tick 介面，持久化各階段 deadline，不能偽造真人出牌來推進動畫 |
| 主迴圈 `guard<2000` | 整場東風含連莊可能超限，需改為可續跑且有進度 watchdog 的排程；不能超限就退款已知結果牌局 |
| `ctx.seats[].bot` 與付款過濾 | 已鎖額真人即使代打、離場仍依最初帳號結算；不可更改 bot 標記導致 `payHand` 濾掉其派彩，需分離 controller 與 financial owner |
| 空位 Bot | 入場前補位，東風戰中不讓新帳號取代既有財務席。純 Bot 份額由平台既有帳本的莊／Bot 準備金處理，不能憑空加減真人款項；具體 ledger 能力須聯測 |
| `liability/minStake` | casual 入場鎖 `250*ctx.limits.unit`，檢查四席各自 stakeCap 足額且不超 maxStake；不足拒絕入場，不採短碼。ranked 依契約返回 0 |
| `maxPayoutMultiple` | 固定4（含本金），整桌四份入場為最高總可派；不得另設超出已鎖額的役滿追加扣款 |
| `shutdown` 註解為重啟退款 | 與本作開局後保留座位續打不同，正式部署需恢復已開牌局的 state、種子位置、deadline、owner 與結算紀錄；不能直接沿用退款策略 |

這些平台差異以**獨立整合變更**處理，保留原 framework 契約與測試，不能私自把文件中的「不要改」當成已獲准改平台核心。優先向平台既有擴充點接入；不足部分交付明確介面差異和適配測試。先完成麻雀模組與可重現整合結果，再判斷需要的平台變更。

## 9. 紅蘿蔔與持久恢復

沿用現有 `carrotSettlement`：終局先派剩餘供託使點數總和回 100,000，再按 (最終點數−25,000)/25,000 換算入場額。每人最大虧損封頂入場額；負分不額外扣錢，總派彩等於四份鎖額。封頂不足的盈利按比例分配，整數尾數用固定初始座序的最大餘數法。不加馬點、頭名獎金或手續費。

- 狀態：`reserved → playing → finalizing → settled`；入場未開牌失敗可 `voided`。已開牌故障先恢復，不由任一客戶端請求取消或退款。
- 開局保留 `matchId + financialOwner[4] + lockedEntry + rulesVersion`；每局每筆 event/settlement 有唯一 ID 和遞增 revision。伺服器序列化處理，資料庫 compare-and-swap／同等交易防止雙主機同時推進。
- 先持久化完整結果，再發事件；事件只保證可重送，接收方依 ID 去重。結果入帳及終局狀態須具備原子／冪等保證，不假設網絡只送一次。
- 終局錢包以 `matchId:final` 作固定冪等鍵，重啟／重試都使用同一鍵；若平台 API 沒有該能力，列為上線阻擋項，不以 UI 標記假裝解決。
- 結算 API 超時為結果未知：先查該鍵交易狀態再安全重試，不創建新結算鍵。畫面寫「結算確認中」，保留點數與明細，禁止再次開局花用未確定款項。
- 全員離線：照常由 Bot 打完並派回原帳號；持久化可查結果，下次登入顯示未讀賽果。不是所有玩家離線就取消場次。
- 伺服器恢復：取得房間單一租約，從保存牌山位置和 revision 恢復，已過期的出牌轉代打、搶牌依未決者放過；已計分不重算，已派彩不再派。
- 種子／快照毀損時停止房間並保留帳本紀錄，顯示維護；由平台可稽核補償流程處理，不能自動虛構牌局或抹掉已支付交易。

## 10. 上線驗收矩陣與實作次序

每項新增規則必須能以固定種子／fixture 重現；Demo 可強制展示，正式對局仍由合法判定觸發。測試核心斷言是點數／帳本守恆、狀態可推進、私隱及冪等，不只是截圖相似。

1. **計分核心**：大三元／大四喜責任各測莊閒、自摸、他人放銃、責任者放銃、複合役滿、本場、雙響；無責任觸發對照；例子的 16,000／48,000 與總和必須精確。
2. **流局滿貫**：單人莊閒、多人成立互付、有本場供託、0 點終局；中張牌已被叫走、自己副露／暗槓、空河、被叫走么九牌、最後張榮和及途中流局均不誤判；不公開手牌。
3. **搶牌**：吃先按但碰未決、碰先按但榮和未決、雙響兩種到達順序、三個有資格僅兩個宣告、真正三宣告、搶槓、截止前後、重送、舊 socket。
4. **演出 Demo**：雙響兩支片／混合片圖／皆無片、單手多役滿選片、三倍以上數字與圖文字無矛盾、流局滿貫多人河牌、包牌轉移明細、三家流局；四角色均可選。
5. **故障／同步**：兩至四個真實連線，在每個演出階段重連／退背景／換裝置；壞圖片、影片 404／停滯、無聲音；其他裝置仍準時推進，無重複付款。
6. **framework 整合**：整場超過 2,000 推進、全部離線、原帳號由 Bot 打到結束、時限精確 30/20/10 與 12、階段無 actors 仍續跑、伺服器重啟恢復、Bot 與真人混桌帳本守恆。
7. **錢包故障注入**：鎖額不足不開局；付款成功但回覆丟失；提交前後殺進程；重複 final 事件；總鎖額＝總派彩，每人只記一次結算。

交付順序：計分核心與固定規則 → 合法 Demo／演出計畫 → framework 麻雀模組接入 → 平台介面差異聯測及恢復／帳本 → 四裝置端到端驗收 → 公開真人模式。既有公開 Bot 版維持可玩，未通過的功能不可在規則頁冒稱已支援。
