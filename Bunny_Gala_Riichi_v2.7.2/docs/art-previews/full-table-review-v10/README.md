# 遊戲構圖滿載檢查 V10

這是 Chromium 中實際渲染的獨立 3D 排位預覽，使用遊戲現有牌面、牌身與蘿蔔模型；不是生成式圖片，也不是正式遊戲截圖。正式遊戲尚未套用此構圖。

- [A：完整手牌與滿河](full-hands-clean.jpg) · [分區版](full-hands-zones.jpg)
- [B：每家四組明槓](four-kans-clean.jpg) · [分區版](four-kans-zones.jpg)

兩種情境都有四家各 24 張牌河、17 幢兩層牌山。A 有玩家 14 張、三家各 13 張暗牌與四支河前蘿蔔棒。B 有每家 16 張明槓，玩家兩張暗牌，其餘各一張；副露者不放立直棒。這是各區最大容量壓力展示，並非合法的同一副 136 張牌局，「餘42張」只是資訊樣式。

玩家手牌這次使用獨立正交鏡頭，保留 100:136 直身牌面與少量頂面。其餘牌沿用 V8 桌面投影，目的是把未解決的問題顯示出來，不能視為已通過外觀驗收。

## 畫面上仍存在的問題

1. 三家暗牌投影過扁，黑背形狀與已認可的外觀不一致。需要調整立面投影與暗牌展示角度。
2. 牌河與副露的側面厚度、圓角及金邊不夠明顯；容量放得下不等於材質外觀正確。
3. 對家四組副露與牌山的視覺間距偏小，即使九點遮擋檢查通過，仍需增加可辨識的空隙。
4. 玩家獨立手牌仍偏平光，應補強圓角、細金邊、接觸陰影，並校準與桌上牌的視覺尺寸。副露情境已把兩張手牌放到左側，避免遮住自己的副露。
5. 左右與對家角色的頭部大小仍不完全一致；對家分數卡也離角色較遠。
6. 這輪只輸出桌面版，未驗證電話版的最終可讀性與操作範圍。

## 自動檢查的範圍

逐張計數、桌面內邊界、世界模型交疊、落地、每張公開牌面九點遮擋、中央及周邊 UI 對公開牌面的遮擋。獨立手牌是第二次渲染的展示層，其螢幕占位需另外目視檢查；原本的世界座標檢查只代表預留帶，不代表此展示層已全面通過。
